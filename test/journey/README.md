# Journey runner

`run.mjs` is retired and only refuses, with exit 2. It drove `claude -p`, and print-mode journey runs are no longer allowed.

The plugin's T1-T5 results in `plugins/claude-code/README.md` stand at their recorded commits. The old runner is reachable through git history at `cdb09e4`.

In a row's `summary.json`, `captureAttempts` lists the capture calls the permission layer denied. `captures` lists every capture call as `{turn, name, outcome}`, with outcome `accepted`, `denied`, `error` or `no_result` (the stream holds no result for the call, so how it went is not known); a denial record with no `tool_use_id` pairs with a denied call of the same name, so that call is listed once.

## Hook rows

Five rows of the SDK harness (`lib/rows.mjs`, ids in `HOOK_ROW_NAMES`) observe the plugin's own hooks. The plugin loads through `--plugin-dir` as on every plugin row, and its hooks load with it. Each of these rows also sets `includeHookEvents`, so the stream carries the SDK's `hook_started`, `hook_progress` and `hook_response` messages. Every one goes to `stream.jsonl`, and `summary.json` lists each turn's as `hookEvents` (`hook_event`, `hook_name`, `subtype`, `text`). The SessionStart messages arrive before init. On these rows they are read, not a load stop, and every other row keeps its plain note. The output field of a `hook_response` is not documented, so its text is every non-empty string in the message outside the identifying and status fields.

All five are connector rows in a new empty working directory, with the plugin and a fresh config directory. Four have auto memory off; T1-auto-memory-hook has it on. On every row, a capture before the person's yes is FAIL, never INCONCLUSIVE. INCONCLUSIVE exits 1 and is never a pass.

## Permission guard (PERM-1)

Every session runs in `dontAsk` mode, and the harness checks that at the one place a query starts (`sessionOptionFault` in `lib/guards.mjs`). `test/perm1-guard.test.mjs` and the session guard tests in `test/auth-and-guards.test.mjs` cover it. The SDK docs describe the modes in [Agent loop, permission mode](https://code.claude.com/docs/en/agent-sdk/agent-loop#permission-mode) and [Permissions, permission modes](https://code.claude.com/docs/en/agent-sdk/permissions#permission-modes).

- What the suite shows: every session is `dontAsk` with no `canUseTool` and no bypass flag; a capture the turn did not allow is a recorded denial, never a prompt; and the five other modes (`default`, `bypassPermissions`, `acceptEdits`, `plan`, `auto`) are refused before any query.
- What it cannot show: what the SDK itself does in `default` or `bypassPermissions` mode, or whether a person would see a prompt. No session runs in those modes, and the fake client has no callback. What the docs say about those modes is quoted in the test file's header, not measured.
