# Journey runner

`run.mjs` is retired and only refuses, with exit 2. It drove `claude -p`, and print-mode journey runs are no longer allowed.

The plugin's T1-T5 results in `plugins/claude-code/README.md` stand at their recorded commits. The old runner is reachable through git history at `cdb09e4`.

## Hook rows

Three rows of the SDK harness (`lib/rows.mjs`, ids in `HOOK_ROW_NAMES`) observe the plugin's own hooks. The plugin loads through `--plugin-dir` as on every plugin row, and its hooks load with it. Each of these rows also sets `includeHookEvents`, so the stream carries the SDK's `hook_started`, `hook_progress` and `hook_response` messages. Every one goes to `stream.jsonl`, and `summary.json` lists each turn's as `hookEvents` (`hook_event`, `hook_name`, `subtype`, `text`). The SessionStart messages arrive before init. On these rows they are read, not a load stop, and every other row keeps its plain note. The output field of a `hook_response` is not documented, so its text is every non-empty string in the message outside the identifying and status fields.

All three are connector rows in a new empty working directory, with the plugin, a fresh config directory and auto memory off. On every row, a capture before the person's yes is FAIL, never INCONCLUSIVE. INCONCLUSIVE exits 1 and is never a pass.

- **T3b** (one turn, "Reply with the single word ready."; Skill and ToolSearch). PASS: the plugin's SessionStart reminder (`BANNER` in `session-banner.mjs`, imported, not copied) appears in exactly one SessionStart `hook_response`, the CLI hook's sentence "Quadron is connected, and this person keeps a record of their own expertise in it." appears in no hook output, and no capture tool is called. FAIL: the reminder twice, or from another event, or missing while other hook output was seen; the connected sentence anywhere; any capture. INCONCLUSIVE: no `hook_response` text at all, which means the SDK surfaced no hook output.
- **T2-hook** (one turn, "I decided we bill annually only; monthly plans are ruled out."). The prompt hits the prompt trigger's capture phrases and none of its recall phrases (checked in `test/hook-rows.test.mjs` against `prompt-trigger.mjs`). The read tools are allowed, and the capture tool is visible but not allowed, as on T4O-S. PASS: a UserPromptSubmit hook event whose recorded text holds the prompt trigger's capture steer (`CAPTURE_TEXT` in `prompt-trigger.mjs`, imported as `T2_HOOK_STEER`), an offer at "annually" (the `isOffer` heuristic), and no capture. FAIL: any capture, allowed or denied ("captured before confirmation"), or no offer. INCONCLUSIVE: offer and no capture, but no UserPromptSubmit event: "hook event not observed; tool-call order only"; or the event without the steer text, which needs a hand read of the evidence.
- **T1-hook** (two turns, one session; turn 2 resumes turn 1, as on T4). Turn 1 asks for a scratch note holding the person's own decision ("My standard: every release note names the exact command that was run.") written with the Write tool to `CLAUDE.md` in the row's working directory (`hookWriteTarget`). That turn alone approves one rule, `Edit(//<working directory>/CLAUDE.md)`, composed from the working directory's real path. Edit rules cover Write, and a Windows path takes the `//c/...` form. A working directory whose real path differs (a symlink or a short name) refuses the row before any reservation or call, exit 2. Write and Edit are shown on both turns, and every other write is denied. Turn 2 is the person's yes ("Yes, keep it in Quadron: every release note names the exact command that was run.") with the capture tool allowed, as on T4. PASS: the Write to `CLAUDE.md` ran, a PostToolUse `hook_response` came after it or hook text after it holds the memory trigger's instructions-file steer (`T1_HOOK_STEER`, derived from `contextText` in `memory-trigger.mjs`), turn 1 offered at "exact command" and did not capture, and turn 2 made exactly one accepted capture whose input holds "exact command that was run" (any case). FAIL: a capture in turn 1; a write to any other path, on either turn, or any other file in the working directory; no Write or no offer (turn 2 is then never spent); turn 2 with no capture, more than one, or one without the person's words. INCONCLUSIVE: everything else holds, but no PostToolUse event after the Write: "hook event not observed; tool-call order only"; or only `hook_started`/`hook_progress` after it, which the note says. A weak or missing observation never stops turn 2.

T1-hook exercises the plugin's `Edit(**/CLAUDE.md)` filter, not its auto-memory filter `Edit(~/.claude/projects/**/memory/**)`. The auto-memory filter stays untested here: the harness's config directory is not under the home `.claude` directory.
